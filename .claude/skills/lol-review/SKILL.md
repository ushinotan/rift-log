# ランク戦の振り返り

このリポジトリ（rift-log）のルートで作業する。コマンドは **必ず `npm run -s`**（`-s` で npm のヘッダー行を抑え、JSON だけを出力させる）。

## 手順

### 1. 新しい試合を取り込む

```bash
npm run -s sync
```

- 標準出力に新しく取り込んだ matchId が1行ずつ出る（進捗は標準エラー）。
- 「API キーが無効か期限切れ」と出たら、そこで止めてユーザーに伝える：
  開発キーは24時間で失効するので https://developer.riotgames.com/ で再発行し、`.env` の `RIOT_API_KEY` を書き換えてもらう。キーを自分で入力・推測しない。
- 「試合を取り込んで」だけを頼まれた場合は、取り込み結果を報告して終わる（振り返りは書かない）。

### 2. 振り返り待ちの試合を確認

```bash
npm run -s pending
```

振り返りがまだない試合の matchId が古い順に出る。0件なら「振り返り待ちの試合はありません」と報告して終わる。
**古い順に1試合ずつ** 3〜4 を繰り返す（前の試合の振り返りが、次の試合の `recentHistory` に反映されるため）。

### 3. 試合データを読む

```bash
npm run -s match -- <matchId>
```

主なフィールド：

| フィールド | 内容 |
|---|---|
| `summary` | 日時・結果・試合時間・チャンピオン・ロール・対面・パッチ |
| `me` / `opponent` / `diffVsOpponent` | 自分と対面のスタッツと差（自分 − 対面） |
| `laningDiffs` | 5/10/15/20分時点の対面とのゴールド差・CS差、チームのゴールド差 |
| `myDeaths` | 自分のデス（時刻・倒した相手・アシスト・`エリア`）。`エリア` は自陣基準の簡易判定（自陣/敵陣ベース、トップ/ミッド/ボットレーン、川、自陣/敵陣ジャングル）。「敵陣ジャングルでのデスが2回」のように数字で使える |
| `objectives` | 味方/敵のタワー・ドラゴン・ヴォイドグラブ・ヘラルド・バロン数、ファーストブラッド/タワー/ドラゴン |
| `objectiveTimeline` / `killTimeline` | 時系列イベント（`me` に自分の関与：キル/デス/アシスト/ラストヒット） |
| `build` / `skillOrder` | アイテムの購入・売却順、スキル順 |
| `recentHistory` | この試合より前の直近5試合（スタッツ・オブジェクト・その試合の改善点と目標） |
| `existingReviewItems` | これまでに使った「項目」名の一覧 |

### 4. 振り返りを書く

次の JSON を作る。

```json
{
  "良かった点": [{ "項目": "短い見出し", "詳細": "データを引用した説明" }],
  "改善点":     [{ "項目": "短い見出し", "詳細": "データを引用した説明" }],
  "次の目標":   [{ "項目": "短い見出し", "詳細": "具体的で測れる目標" }]
}
```

- **良かった点 3〜5個、改善点 3〜5個、次の目標 1個**。すべて日本語。
- **数字は必ずデータから引用する**（例：「CSは対面に65差で勝ち（245 vs 180）」「10分時点でゴールド +820」「14:32 にリヴェン・リー・シンに倒された」）。データにない数字を作らない。
- データから断定できない推測（意図・判断の理由・見えていなかった情報など）には文末に **「（推定）」** を付ける。
- **項目は短く、表記を揃える**。`existingReviewItems` に同じ意味の項目があればその文言をそのまま使う（傾向画面で回数を集計するため）。例：「ヴォイドグラブを取られた」「中盤のデス」「視界確保」「CS」。
- `recentHistory` を見て、**同じ改善点が続いていたら必ず指摘する**。例：「ヴォイドグラブを3試合連続で取られている（0-3, 0-6, 1-5）」。前回の「次の目標」を達成できたかにも触れる。
- 次の目標は1試合で確認できる具体的なもの（例：「15分までのデスを0にする」「CS/分 7.5 以上」）。
- チャンピオン・アイテム・ルーン・スペル名は `match` の出力にある日本語名をそのまま使う（英語名や独自の表記にしない）。

JSON はスクラッチ用の一時ファイル（リポジトリの外、または `data/` 配下）に UTF-8 で書く。

### 5. 保存する

```bash
npm run -s review:add -- <matchId> <JSONファイル>
```

同じ試合の振り返りは上書きされる。件数の注意が出たら直して保存し直す。

### 6. チャットで報告

試合ごとに短く：日時・チャンピオン vs 対面・結果・KDA、良かった点と改善点の見出し（各1行）、次の目標。
連続している改善点があれば強調する。最後に `npm run dev` → http://localhost:5173 で詳細が見られることを一言添える。
